# 代理Ftp服务

> `Ftp`分了两种模式，主动模式（`PORT`）和被动模式（`PASV`），连接都是客户端发起连接通过`21`端口；主动模式的话是服务器发起数据连接，一般通过服务器的`20`端口，但是客户端会随机生产数据端口；被动模式的话是客户端发起数据连接，服务端端口是随机的。
>
> 我们想通过代理服务器访问`Ftp`服务，以解决`Ftp`服务器地址可能会修改的问题。

## 调研

### Nginx

通过`Nginx`的`Stream`模块四层透传`Tcp`流量，支持被动模式`PASV`，但是需要`Ftp`服务器修改`PASV`对外`Ip`为代理服务器`Ip`，同时固定被动端口段，配置多端口段转发写法笨重，不擅长批量连续端口。如果是主动模式的话，跨代理拓扑可能会直接失败，同网段的话会导致流量割裂，控制流量走`Nginx`，数据流量直接后端`Ftp`服务器直连客户端，绕过代理。

### Squid

`Squid`理论支持主动和被动模式，如果使用`Squid`代理的话，`Squid`本身是`Http`代理，`Ftp`走 `ftp://` 协议代理，`Squid`不能做`Ftp`透明代理，客户端必须显式配置代理才能使用，比如：`curl -x http://192.168.1.100:3128 ftp://ftpuser:ftppass@10.122.10.217`。被动模式好处是不需要修改`PASV`对外`Ip`，主动模式也会存在类似`Nginx`的问题。

### HAProxy

`HAProxy`也是四层`Tcp`代理，默认不会修改`FTP`报文内部的`PORT/PASV`载荷里的`IP`地址，企业运维最稳，且友好支持监听连续被动端口。被动模式下需要修改`PASV`对外`Ip`，主动模式也会存在类似`Nginx`的问题。

### 内核Ftp ALG

被动模式配置了`PASV`对外`Ip`后，存在无法直连的弊端，如果不想修改`Ftp`服务器配置，可以通过`Linux`系统内核`FTP ALG（nf_conntrack_ftp + iptables NAT）`方案实现，且无需手动配置代理。`ALG`模块负责改写`FTP`应用层`PASV`报文，`iptables`或者`firewalld`负责做`DNAT`端口转发，两者必须配合使用，缺一不可。同时支持主动和被动模式，主动模式也会存在类似`Nginx`的问题。

## 配置Ftp ALG

### 加载Ftp ALG内核

```shell
# 加载模块
modprobe nf_conntrack_ftp
modprobe nf_nat_ftp

# 设置开机自动加载
cat >> /etc/modules-load.d/ftp-nat.conf <<EOF
nf_conntrack_ftp
nf_nat_ftp
EOF
```

### 开启Conntrack支持

通过`sysctl`开启`Conntrack helper`支持。

```shell
cat >> /etc/sysctl.conf <<EOF
# 允许自动加载conntrack helper
net.netfilter.nf_conntrack_helper = 1
EOF
sysctl -p
```

### DNAT转发配置

开启内核`IP`转发。

```shell
echo "net.ipv4.ip_forward = 1" >> /etc/sysctl.conf
sysctl -p
```

使用`firewalld`托管防火墙。

```shell
firewall-cmd --list-all
# 开启ip转发，没有masquerade，外部访问映射端口，数据包能到达后端服务器，但后端服务器回包不知道怎么走回客户端，直接不通
firewall-cmd --add-masquerade --permanent
# DNAT端口转发
firewall-cmd --add-forward-port=port=21:proto=tcp:toaddr=10.122.10.217:toport=21 --permanent
firewall-cmd --reload
```

### 放行防火墙端口

`service=ftp` 在`firewalld`内部会自动关联加载`ftp helper`，配合上面`sysctl`生效。

```shell
firewall-cmd --list-all
firewall-cmd --add-service=ftp --permanent
firewall-cmd --reload
```

### 验证模块是否正常

```shell
# 查看模块是否加载
lsmod | grep ftp
```

### 服务器变更维护

```shell
# 删除21端口DNAT转发，参数必须和add时一模一样
firewall-cmd --remove-forward-port=port=21:proto=tcp:toaddr=10.122.10.217:toport=21 --permanent

# 再新增DNAT端口转发，修改Ip
firewall-cmd --add-forward-port=port=21:proto=tcp:toaddr=10.122.10.219:toport=21 --permanent
firewall-cmd --reload
```

### 日志排查

```shell
# 实时监控 conntrack 事件（新建/销毁/expect预期）
yum install conntrack-tools
conntrack -E -p tcp|grep 21

# 在网关抓21端口控制流
yum install tcpdump
tcpdump -nn -i any port 21 -vv
```
