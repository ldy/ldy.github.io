# Gitlab迁移

> 信创改造，需要将GitLab从CentOS7迁移到Kylin Server 10 SP2（含仓库、用户等配置），记录其中遇到的问题。

## 下载

通过如下命令查看`Centos7`上安装的`Gitlab`版本，我的是`gitlab-ce-16.11.5-ce.0.el7.x86_64`版本。

```shell
rpm -qa | grep gitlab-ce
cat /opt/gitlab/version-manifest.txt | head -1
```

新旧服务器`GitLab CE/EE`版本必须完全相同（如16.11.5，不能跨大版本），麒麟用`el8 RPM`包（麒麟`V10`兼容`RHEL8`生态），如果下载`el7`或者`el9`的`RMP`包安装时会异常，[下载链接](https://packages.gitlab.com/gitlab/gitlab-ce/el/8/x86_64/Packages/g/gitlab-ce-16.11.5-ce.0.el8.x86_64.rpm)。

![image-20260722161552829](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-10-15-Gitlab%E8%BF%81%E7%A7%BB-image-20260722161552829.png)

## 安装

`Kylin`服务器上执行`rpm -ivh gitlab-ce-16.11.5-ce.0.el8.x86_64.rpm`等待安装完成即可。

![image-20260722161532159](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-10-15-Gitlab%E8%BF%81%E7%A7%BB-image-20260722161532159.png)

## 备份

```shell
# Centos7停机
gitlab-ctl stop
gitlab-ctl status

# Centos7启动这两项备份依赖服务
gitlab-ctl start postgresql gitaly

# 完整备份，包含仓库、用户、CI制品、LFS、容器镜像
# 备份文件路径：/var/opt/gitlab/backups/
# 文件格式：1780000000_2026_06_29_16.8.1_gitlab_backup.tar
# 记录时间戳：1780000000_2026_06_29_16.8.1
gitlab-backup create
```

![image-20260722162529019](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-10-15-Gitlab%E8%BF%81%E7%A7%BB-image-20260722162529019.png)

## 拷贝

```shell
# 备份仓库、用户等文件，备份文件路径一定要放在/var/opt/gitlab/backups目录，否则执行还原的时候会报错
scp /var/opt/gitlab/backups/1784598136_2026_07_21_16.11.5_gitlab_backup.tar root@10.122.10.215:/var/opt/gitlab/backups

# 备份配置文件，主要修改了external_url访问地址和端口
scp /etc/gitlab/gitlab.rb root@10.122.10.215:/etc/gitlab
# 备份加密密钥文件，默认新安装机器没该文件
scp /etc/gitlab/gitlab-secrets.json root@10.122.10.215:/etc/gitlab
```

## 还原

```shell
# 更新配置，上一步替换了gitlab.rb、gitlab-secrets.json，先执行了该步骤，估计可以省略后面再执行该步骤
gitlab-ctl reconfigure

# 设置权限，备份文件属主必须是git:git，否则执行还原的时候会报错
chown git:git 1784598136_2026_07_21_16.11.5_gitlab_backup.tar
chmod 600 1784598136_2026_07_21_16.11.5_gitlab_backup.tar

# 恢复备份，文件名只需要填备份文件名中的时间戳
gitlab-backup restore BACKUP=1784598136_2026_07_21_16.11.5
```

## 启动

```shell
# 更新配置
gitlab-ctl reconfigure
# 重启
gitlab-ctl restart
# 查看状态
gitlab-ctl status

# 放开防火墙
firewall-cmd --zone=public --add-port=80/tcp --permanent
systemctl reload firewalld

# 设置自启动
systemctl enable gitlab-runsvdir.service
systemctl status gitlab-runsvdir.service
```

当`gitlab.rb`使用默认文件时，`external_url`配置为`external_url 'http://gitlab.example.com'`，`gitlab`默认通过主机`ip`的`80`端口访问如`http://10.122.10.215`，此时虽然能正常访问，但是项目显示的克隆地址是`git@gitlab.example.com:xxx/xxx.git`，未显示真实`Ip`无法拉取，手动修改为`git@10.122.10.215:xxx/xxx.git`才可拉取。

## 测试

通过`Idea`拉取`git@10.122.10.215:xxx/xxx.git`项目，提示`Clone failed`。是由于搭建迁移后的`GitLab`服务器，操作系统`SSH`主机密钥和旧服务器不一样，`Windows`本地 `.ssh/known_hosts` 保存了旧服务器的指纹，SSH 认为中间人攻击，直接拒绝连接，删除该文件重新拉取即可。

## 代理访问

有时候，当需要同时在生产网和测试网访问`Gitlab`时，可以通过带双网卡的前置`Nginx`代理访问，同时支持`Http`和`SSH`访问，且可以将页面的克隆地址改成代理地址，需要`--with-stream`和`--with-http_sub_module`模块的支持，无需更改`Gitlab`配置。

```nginx
# stream模块ssh协议代理
server {
    listen 10.122.10.218:9022;
    proxy_pass 10.122.10.215:22;
}
server {
    listen 10.11.42.218:9022;
    proxy_pass 10.122.10.215:22;
}
```

```nginx
# Http协议代理，proxy_set_header Host必须是$http_host参数带端口，否则会导致转发后无法访问
# =============================================
# 生产入口：10.122.10.218:9080
# =============================================
server {
    listen 10.122.10.218:9080;
    server_name 10.122.10.218;

    location / {
        proxy_pass http://10.122.10.215:80;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 生产网段：把后端GitLab原生地址替换为【生产代理地址】
        sub_filter "http://10.122.10.215" "http://10.122.10.218:9080";
        sub_filter "git@10.122.10.215:" "ssh://git@10.122.10.218:9022/";

        sub_filter_once off;
        sub_filter_types application/json text/plain;
    }
}

# =============================================
# 测试入口：10.11.42.218:9080
# =============================================
server {
    listen 10.11.42.218:9080;
    server_name 10.11.42.218;

    location / {
        proxy_pass http://10.122.10.215:80;

        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;


        # 测试网段：后端原生地址替换为【测试代理地址】
        sub_filter "http://10.122.10.215" "http://10.11.42.218:9080";
        sub_filter "git@10.122.10.215:" "ssh://git@10.11.42.218:9022/";

        sub_filter_once off;
        sub_filter_types application/json text/plain;
    }
}
```

此时，可以同时通过`http://10.122.10.215` `Gitlab`部署机器和`http://10.122.10.218:9080` `Nginx`代理访问，需要注意的是，通过`SSH`协议克隆地址的时候`git clone git@10.122.10.215:cznsh/tl/weloan/ccc.git`是简写形式隐式使用`SSH`协议，但缺乏直接指定端口号的机制，由于代理协议有端口，使用完整的`SSH URL`格式，在`URL`中显式指定端口号`git clone ssh://git@10.122.10.218:9022/cznsh/tc.git`，否则会拉取失败。当在`~/.ssh/config`文件配置密钥时，需要指定的`Ip`为代理地址`10.122.10.218`而不是`10.122.10.215`，否则会一直提示输入`10.122.10.218`的密码而无法拉取仓库。如果拉取失败，可以通过`ssh -p 9022 git@10.122.10.218 -v`命令测试连通性过程详情。
