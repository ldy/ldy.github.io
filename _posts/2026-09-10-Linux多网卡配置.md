# Linux多网卡配置

> 工作环境限制，不同的网络环境只能访问对应网段的网站、应用，这时通过安装双网卡且做对应配置后可以实现同时访问的需求。

## 设置网卡

![image-20260627113511411](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-09-10-Linux%E5%A4%9A%E7%BD%91%E5%8D%A1%E9%85%8D%E7%BD%AE-image-20260627113511411.png)

同时连接多块网卡后，通过`ipconfig`、`ip addr`、`nmcli device status`命令对比查看网络状态，确认硬件已经存在。

![image-20260627113532914](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-09-10-Linux%E5%A4%9A%E7%BD%91%E5%8D%A1%E9%85%8D%E7%BD%AE-image-20260627113532914.png)

进入`/etc/sysconfig/network-scripts`，新增网卡之后还是只有一个网卡配置文件`ens160`，复制现有网卡配置生成`ens192`模板。

```shell
cd /etc/sysconfig/network-scripts/
cp ifcfg-ens160 ifcfg-ens192
vim ifcfg-ens192
uuidgen
```

设置`ens192`网卡，双网卡只能一张网卡设置`DEFROUTE=yes`，另外一张`no`，且只有一张网卡需要设置默认网关`GATEWAY`，避免路由冲突断网，`UUID`通过`uuidgen`命令生成替换，并修改`DEVICE`和`NAME`名称。

```shell
TYPE=Ethernet
PROXY_METHOD=none
BROWSER_ONLY=no
BOOTPROTO=none
DEFROUTE=no
IPV4_FAILURE_FATAL=no
IPV6INIT=yes
IPV6_AUTOCONF=yes
IPV6_DEFROUTE=yes
IPV6_FAILURE_FATAL=no
IPV6_ADDR_GEN_MODE=stable-privacy
NAME=ens192
UUID=e0f4b292-8190-4fb6-969b-d745203c6b77
DEVICE=ens192
ONBOOT=yes
IPADDR=10.xx.xx.xx
PREFIX=24
GATEWAY=
DNS1=
IPV6_PRIVACY=no
```

`Centos8`及以上和`Kylin-Server-10-SP2`系统，执行`systemctl restart NetworkManager`命令重启网络使配置生效。

## 查看路由配置

```shell
# 查看路由表
ip route show
route -n
```

![image-20260627152610828](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-09-10-Linux%E5%A4%9A%E7%BD%91%E5%8D%A1%E9%85%8D%E7%BD%AE-image-20260627152610828.png)

`proto kernel`代表内核自动生成，只要网卡配置`IP`、网卡`UP`就自动出现，不是手动静态路由；`scope link`表示链路本地路由，代表该网段和本机网卡二层直连，不需要网关，直接`ARP`通信。

通过`ip route get 10.xx.xx.xx`命令，测试流量走哪个网关。

![image-20260627155013119](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-09-10-Linux%E5%A4%9A%E7%BD%91%E5%8D%A1%E9%85%8D%E7%BD%AE-image-20260627155013119.png)

## 命令临时修改路由配置

通过修改路由配置，实现所有`ip`默认走`ens160`网关，某几个网段走`ens192`网关，实现同时访问不同网络。

`route`命令是早期`Linux`发行版使用的路由管理工具，但已被 `ip route` 取代；`ip route` 命令提供了更丰富的功能，支持更复杂的路由配置，现在`Linux`发行版建议使用 `ip route` 进行路由管理。

| 功能         | route                                                      | ip route                                            |
| ------------ | ---------------------------------------------------------- | --------------------------------------------------- |
| 查看路由表   | route -n                                                   | ip route show                                       |
| 添加静态路由 | route add -net 10.11.0.0 netmask 255.255.0.0 gw 10.11.42.1 | ip route add 10.11.0.0/16 via 10.11.42.1 dev ens192 |
| 删除静态路由 | route del -net 10.11.0.0 netmask 255.255.0.0 gw 10.11.42.1 | ip route del 10.11.0.0/16 via 10.11.42.1            |
| 设置默认网关 | route add default gw 10.11.42.1                            | ip route add default via 10.11.42.1 dev ens192      |
| 删除默认网关 | route del default gw 10.11.42.1                            | ip route del default                                |

```bash
# route命令添加临时路由，无需重启网络服务
route add -net 10.11.0.0 netmask 255.255.0.0 gw 10.11.42.1
route add -net 10.12.0.0 netmask 255.255.0.0 gw 10.11.42.1
route add -net 10.4.0.0 netmask 255.255.0.0 gw 10.11.42.1

# ip route添加临时路由，无需重启网络服务
ip route add 10.11.0.0/16 via 10.11.42.1 dev ens192
ip route add 10.12.0.0/16 via 10.11.42.1 dev ens192
ip route add 10.4.0.0/16 via 10.11.42.1 dev ens192
```

![image-20260627161441671](https://cdn.jsdelivr.net/gh/ldy/ldy.github.io@master/screenshot/2026-09-10-Linux%E5%A4%9A%E7%BD%91%E5%8D%A1%E9%85%8D%E7%BD%AE-image-20260627161441671.png)

使用`route`、`ip route`命令添加的路由，机器重启或者网卡重启后路由就失效了，是临时的。

## 文件永久修改路由配置

设置永久路由的话，需要在配置文件中进行修改。按照`Linux`启动的顺序，`rc.local`里面的内容是在`Linux`所有服务都启动完毕，最后才被执行的，在`rc.local`中添加路由会存在`NFS`无法自动挂载问题；`Centos8`及以上和`Kylin V10 SP2`系统默认使用`NetworkManager`，不识别、不加载`static-routes`配置文件；推荐使用`route-interface`文件的方式进行配置。

### rc.local文件

路径为`/etc/rc.local`，配置文件内容语法与`route`和`ip route`命令一致，设置完后需要执行`chmod +x /etc/rc.local`命令确保文件具有执行权限。

### static-routes文件

以`Centos7`为例，路径为`/etc/sysconfig/static-routes`，该文件不存在的话就手动建立一个这样的文件，该配置文件的语法如何呢？`static-routes`其实在被`network`这个脚本调用的，打开`/etc/rc.d/init.d/network`这个脚本进行分析。

```shell
# Add non interface-specific static-routes.
if [ -f /etc/sysconfig/static-routes ]; then
	if [ -x /sbin/route ]; then
		grep "^any" /etc/sysconfig/static-routes | while read ignore args ; do
			/sbin/route add -$args
		done
	else
		net_log $"Legacy static-route support not available: /sbin/route not found"
	fi
fi
```

`network`在执行的时候到`static-routes`里面寻找`any`开头的行，然后执行`/sbin/route add -$args`命令，相当于手动执行了`route add`脚本，那后面事情就简单了，回到了手动执行的方式，根据前面的说明，正确的脚本就是`any host 10.11.0.100 gw 10.11.42.1`，`network`执行的时候把`any`去掉，获取后面的参数`host 10.11.0.100 gw 10.11.42.1`，最后执行`route add -host 10.11.0.100 gw 10.11.42.1`添加路由。注意这里`host`前面的`-`是~自带的，不需要配置到`static-routes`文件中，最终配置内容如下。

```shell
# 设置网段
any net 10.11.0.0 netmask 255.255.0.0 gw 10.11.42.1
any net 10.12.0.0 netmask 255.255.0.0 gw 10.11.42.1
any net 10.4.0.0 netmask 255.255.0.0 gw 10.11.42.1
# 设置host
any host 10.11.0.100 gw 10.11.42.1
```

### route-interface文件

路径为`/etc/sysconfig/network-scripts/route-interface`，`interface`需要根据实际的网卡换成网卡名，比如我要在`ens192`上加静态路由，那就写`route-ens192`，语法也比较简洁。

```shell
10.11.0.0/16 via 10.11.42.1
10.12.0.0/16 via 10.11.42.1
10.4.0.0/16 via 10.11.42.1
```

使用`systemctl restart NetworkManager`命令重启网络无效，需要使用如下命令。

```shell
# 加载所有网卡配置文件
nmcli connection reload
# 分别重启两张网卡，同时使用down和up，或者单独使用up
nmcli connection down ens160 && nmcli connection up ens160
nmcli connection down ens192 && nmcli connection up ens192

# 勿单独执行网卡down命令，否则会断网
# nmcli connection down ens160
# nmcli connection down ens160

# 或是同时使用ifdown和ifup，或是单独使用ifup命令，勿单独使用ifdown命令，否则会断网
ifdown ens160 && ifup ens160
ifdown ens192 && ifup ens192
```

## DNS按域名分流

双网卡配置`DNS`，比如`ens160`的`DNS`是`11.3.127.13`，`ens192`的`DNS`是`10.12.23.16`，`/etc/resolv.conf`只是简单把两个`DNS`排成列表，系统按顺序挨个尝试比如先去查`11.3.127.13`，该`DNS`不存在这条记录则直接返回`NXDOMAIN`，服务器收到`NXDOMAIN`就停止继续查询下一个`DNS`，不会再去尝试`10.12.23.16`，如果某个域名比如`iamsit.cscloud.hnrcc.bank`只有`10.12.23.16`能解析，那么此时`ping iamsit.cscloud.hnrcc.bank`会导致无法解析。

`Win10`上使用了`Smart Multi-Homed Name Resolution`（智能多宿主名称解析）[^1]技术，会同时向所有适配器的`DNS`发查询，不会出现该问题。下面通过启用`Linux`自带的`systemd-resolved`实现按域名分流`DNS`。

通过`vim /etc/NetworkManager/NetworkManager.conf`命令新增配置启用`systemd-resolved`。

```ini
[main]
#plugins=ifcfg-rh,ibft
dns=systemd-resolved
rc-manager=symlink
```

创建软链接指向 `127.0.0.53`，所有解析请求统一交给`resolved`代理。

```shell
# 先备份
mv /etc/resolv.conf /etc/resolv.conf.bak
# 创建软链接指向stub代理
ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
# 删除软链接
# rm -f /etc/resolv.conf
```

添加域名匹配规则且永久固化。

```shell
mkdir -p /etc/systemd/resolved.conf.d
vim /etc/systemd/resolved.conf.d/split-dns.conf
```

```ini
# split-dns.conf文件内容，域名以.cscloud.hnrcc.bank结尾，强制使用本段内配置的DNS=10.12.23.16查询；FallbackDNS：当上面规则不匹配、且网卡没有提供上游DNS时，自动使用11.3.127.13
[Resolve]
Domains=~cscloud.hnrcc.bank
DNS=10.12.23.16
FallbackDNS=11.3.127.13
```

启动并设置开机自启`resolved`。

```shell
systemctl enable --now systemd-resolved
```

重载网卡配置。

```shell
nmcli connection reload
nmcli connection down ens160 && nmcli connection up ens160
nmcli connection down ens192 && nmcli connection up ens192
```

此时`ping iamsit.cscloud.hnrcc.bank`已经正常解析。
